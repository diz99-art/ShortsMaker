# 1단계: Mac CapCut 호환성 검증

검증일: 2026-10-09. 사용자 원본 미디어 사용·삭제·변경 없음. 외부 업로드 실행 없음.
앱 업데이트나 사용자 기존 프로젝트 변경 없음. 앱 저장소에는 승인받아 새 시험 폴더만 추가했다.

## 조사

- [pyCapCut 공식 저장소 문서](https://github.com/GuanYixuan/pyCapCut/blob/main/english_readme.md):
  이미지·음악·텍스트·SRT·키프레임 초안 생성 기능을 제공한다. Mac/Linux에서 Python 실행은 가능하나,
  생성한 초안의 내보내기는 Windows CapCut에서 진행하도록 안내한다. Mac 앱 지원 보장과 구분해야 한다.
- [pyJianYingDraft 공식 저장소](https://github.com/GuanYixuan/pyJianYingDraft):
  중국판 剪映용이며 CapCut용 저장소를 별도로 안내한다. Mac에서 초안 생성은 가능하지만 자동 내보내기는 지원하지 않는다.
- [pyCapCut 이슈 #13](https://github.com/GuanYixuan/pyCapCut/issues/13):
  사용자 보고에서 Mac CapCut 9.1.0의 빈 `draft_materials` 때문에 이미지·음악 연결이 실패한다.
  제안된 등록 목록 보정은 버전별 역분석 결과이며, 이번 설치 버전 5.9.1에서 효과를 보장하지 않는다.
- [PyPI 배포 정보](https://pypi.org/project/pycapcut/): 실제 설치 패키지 0.0.3을 고정해 시험했다.

조사한 자료만으로 Mac CapCut의 공식 Python SDK나 안정적인 프로젝트 생성 계약을 확인하지 못했다.
비공식 JSON을 직접 생성하는 방식은 버전별 파일 구조와 앱의 소재 관리에 의존한다.

## 환경과 최소 시험

macOS 26.3.1, Python 3.12.15, CapCut 5.9.1, pycapcut 0.0.3, FFmpeg/ffprobe.
앱 설치 정보와 기존 초안 구조는 읽기 전용으로 조사했다. 사용자 프로젝트 내용·기기 식별자를 보고서에 복사하지 않았다.
기존 Mac 초안은 `draft_info.json`, `new_version=132.0.0`을 사용했다.
pycapcut 기본 생성물은 `draft_content.json`, `new_version=140.0.0`, Windows 앱 6.7.0 정보를 사용했다.

합성 미디어: 1080×1920 단색 PNG, 3초 MP3, `한글 자막 검증` 텍스트 0.5~2.5초.
30fps, 이미지·음악 0~3초, 별도 텍스트 트랙. 실제 Suno 음악은 사용하지 않았다.

| 시험 | 앱에서 관찰한 결과 | 판정 |
|---|---|---|
| raw: pycapcut 기본 생성물 | 홈 목록에 나타남, 00:00; 더블클릭 후 편집 화면 전환 관찰 안 됨 | 실패/미완료 |
| mac: draft_info 복사 + 경로·이름·길이 메타데이터 | 00:03 표시, 열기 시 최신 버전 프로젝트라는 업데이트 필요 대화상자 | 실패 |
| version: 설치 버전에 맞춘 new_version/platform | 3초 타임라인, 한글 텍스트 트랙 열림; 이미지·음악 접근 불가, Unsupported Media | 부분 성공 |
| registered: 추가 소재 목록 등록 | 동일한 미디어 접근 오류, 이미지·MP3 재연결 대화상자 | 실패 |

보정은 각각 독립된 복사본에 적용했다. 원본 시험 생성물도 덮어쓰지 않았다.
설치된 시험 폴더: `~/Movies/CapCut/User Data/Projects/com.lveditor.draft/ShortsMaker_probe_20261009_{raw,mac,version,registered}`.
앱이 시험 초안을 열면서 자체 저장 파일과 전역 목록을 갱신할 수 있다. 사용자 기존 초안 파일을 직접 편집하지 않았다.

한글 텍스트가 별도 트랙과 플레이어에 표시되는 것은 관찰했다. 앱에서 글자를 수정하고 재저장하는 검증은
소재 재연결 대화상자 때문에 완료하지 않았다. 이미지와 음악의 정상 재생, 음악 청취, 최종 영상 내보내기,
전환 효과·줌·5개 순위 배치·SRT 앱 가져오기는 검증하지 않았다.

## 테스트와 한계

`pytest`는 합성 초안 생성, 해상도·fps·타임라인·한글·파일 존재,
기존 경로 덮어쓰기 거부, 보정 원본 보존 및 소재 등록 구조를 검증한다.
자동 테스트 통과는 CapCut 앱 호환성 통과가 아니다.

최종 실행: `3 passed in 0.21s`. `ffprobe`는 합성 MP3의 오디오 스트림과 정확히 3.000초를 확인했다.
`git diff --check`도 통과했다. 실제 앱 시험은 위 표의 부분 성공/실패 상태다.

첫 실행에서 최신 main 문서의 `trange_seconds`가 0.0.3에 없어 실패했다.
설치 버전의 마이크로초 `Timerange`로 수정한 후 재시험했다. 실패 출력은 output/capcut-probe-baseline에 남아 있다.
등록 목록 우회책이 5.9.1에서 해결되지 않은 원인은 확정하지 않았다.
앱 권한, 추가 소재 식별자, 버전별 경로 해석 차이 등을 추가 조사해야 한다.

## 다음 단계 제안

현재 Mac에서 CapCut 프로젝트 생성 지원을 제품 기능으로 약속하지 않는다.
후속 호환성 실험은 앱이 직접 만든 **새 합성 프로젝트**에 동일 PNG·MP3를 수동 가져오기하고,
그 초안 복사본과 생성물의 소재 등록/식별자/파일 경로를 비교하는 방식이 적절하다.
해결되면 이미지·음악 재생, 한글 수정·재저장·재열기, 1080×1920/30fps 내보내기까지 통과해야 한다.

해결되지 않으면 다음 개발 단계에서 FFmpeg 영상 클립 + 원본 음악 복사본 + UTF-8 SRT를
CapCut 수동 가져오기용으로 제공하는 경로를 우선 검토한다. 이 대체 결과물 역시 앱 가져오기 검증 전에는 성공으로 보고하지 않는다.
2~4단계 구현은 이번 작업에서 진행하지 않았다.
