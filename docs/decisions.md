# 설계 결정 기록

왜 이렇게 만들었는지 짧게 남긴다. 새 결정은 아래에 덧붙인다.

## 타입 검사(mypy)는 핵심 모듈만 엄격하게, 나머지는 단계적으로

- 결정: 자료 양식 읽기(`quick_parse`, `quick_parse_info`), 순위·숫자 변환(`rank_extract`), 가사(`lyrics`),
  카드 모드(`card_timing`, `card_layers`, `card_mode`)는 엄격 검사. 나머지 모듈은 기본 검사를 하되,
  아직 오류가 남은 모듈은 `pyproject.toml` 의 무시 목록에 두고 고칠 때마다 목록에서 뺀다.
- 이유: 전체 오류 0개를 한 번에 맞추려면 동작 코드를 대량으로 고쳐야 해서 회귀 위험이 크다. 버그가 가장 많이
  나왔고(이름 속 숫자, 공동 순위, 표 열 밀림) 테스트로 묶기 쉬운 핵심 로직부터 막고, CI 는 처음부터 통과하게 둔다.
- 엄격 설정에서 `warn_return_any` 만 끈다: `re.Match.group()` 이 `str | Any` 를 돌려줘서 정규식 코드마다 경고가 난다.

## CI 는 PR 에서 빠른 검사, 렌더 테스트는 main·수동 실행에서만

- 결정: PR 은 실제 MP4 를 인코딩하는 테스트와 두 프로세스 결정성 테스트(`@pytest.mark.slow`, 12개)를 빼고 돌린다. main 에 합쳐질 때와
  수동 실행(Actions → CI → Run workflow)은 전체를 돌리고 커버리지 하한 89% 를 건다.
  브랜치 push 는 PR 에서 검사한다 (같은 검사가 두 번 돌지 않게).
- 줄이는 방법
  - 렌더 테스트 제외: 테스트 시간의 대부분이 영상 인코딩 7~11개였다 (로컬 기준 하나에 15~114초)
  - 설치된 파이썬 폴더 캐시: 요구 사항 파일이 그대로면 `pip install` 을 건너뜀 (pip 캐시는 처음 설치용으로 유지)
  - 커버리지 측정을 `COVERAGE_CORE=sysmon`(Python 3.12 sys.monitoring)으로
  - whisper·demucs·torch 는 CI 에 설치하지 않는다 (처음부터 그랬음. 실제 모델 테스트는 스스로 건너뜀)
- 측정 (GitHub ubuntu-latest, 같은 코드)
  - 전: PR 한 번 16분 5초 (pytest 14분 33초, 301개)
  - 후 첫 실행(캐시 없음): 3분 38초 (pytest 89초, 293개, 캐시 저장 40초 포함)
  - 후 캐시 있음: **2분 50초~2분 57초** (패키지 설치 0초, pytest 82~113초)
  - main·수동 전체 실행(렌더 포함 301개): 14분 42초 — PR 을 기다리게 하지 않는 대신 merge 뒤에 돈다
  - PR 에서 빠진 렌더 테스트는 main 에 합쳐질 때 돌기 때문에, 렌더가 깨지면 merge 직후 main 배지가 빨개진다
- PR 커버리지는 렌더 경로가 빠져 82% 로 낮게 나온다. 배지의 커버리지는 main 전체 실행 값(89.7%)이다.

## README 커버리지 배지는 고정 값 + CI 하한 검사

- 결정: 커버리지 배지는 shields.io 고정 배지(main 전체 실행 값)로 두고, main CI 가 `--cov-fail-under=89` 로 그
  아래로 떨어지면 실패하게 한다.
- 이유: 실시간 배지는 Codecov 같은 외부 서비스 가입이나, CI 가 배지 파일을 올릴 별도 브랜치가 필요하다.
  공개 저장소에는 main 만 올리기로 했으므로 지금은 쓰지 않는다. 공개 뒤 Codecov 를 붙이면 배지 주소만 바꾸면 된다.

## FFmpeg 를 래퍼 없이 직접 호출

- 결정: moviepy 같은 래퍼를 쓰지 않고 `subprocess` 로 `ffmpeg`·`ffprobe` 를 실행한다. 지금 쓰는 카드 방식은 Pillow 로
  그린 프레임을 raw RGB 로 FFmpeg 표준 입력에 흘려 넣는다 (`card_mode.render_video`).
- 이유
  - 출력 규격(1080×1920, 30fps, H.264 yuv420p, AAC 192k, `+faststart`)을 옵션 그대로 정확히 지정한다
  - 실패하면 실행한 명령과 stderr 끝부분을 그대로 보여 줄 수 있다 (`ffmpeg_builder.FFmpegError`)
  - 같은 입력이면 프레임이 똑같이 나온다. 그래서 리팩터링 전후를 framemd5 해시로 비교해 검증할 수 있었다
- 바뀐 점: 첫 버전(classic)은 장면 클립 + xfade 필터였다. 참고 영상의 '확대 + 모션 블러' 전환과 한 글자씩 나오는
  자막을 필터로 만들기 어려워 프레임을 직접 그리는 방식(card)을 추가했다. 모양이 같은 프레임은 다시 그리지 않고 재사용한다.
- 대가: FFmpeg 를 따로 설치해야 하고(brew·apt) 필터 문자열을 직접 관리한다. Homebrew FFmpeg 에 libass 가 없어
  classic 의 가사 자막은 PNG overlay 로 대신한다.

## 화면은 Streamlit

- 결정: 입력·미리보기·제작 버튼을 Streamlit 으로 만든다 (`app.py`, `pages/`).
- 이유: 혼자 쓰는 로컬 도구라 웹 프런트엔드를 따로 만들 필요가 없다. 파이썬만으로 입력 폼, 표 편집(`st.data_editor`),
  장면 미리보기, 영상 재생을 만들 수 있다.
- 지킨 원칙: 화면 코드는 얇게 두고 로직은 `shortsmaker/` 에 둔다. CLI·화면·테스트가 같은 함수를 부른다.
- 대가: 버튼을 누를 때마다 스크립트가 처음부터 다시 실행된다. 그래서 단계가 긴 작업(노래로 자동 제작)은 상태를
  `projects/<이름>/auto.json` 에 저장해 '이어서 하기'로 계속한다. 화면 테스트는 Streamlit `AppTest` 로 한다.

## 채널 배치는 템플릿 파일로 분리

- 결정: 좌표·색·글꼴·효과를 `templates/<채널>/template.json` 에 두고 pydantic `Template` 으로 검증한다.
  코드에 좌표를 쓰지 않는다. 내 컴퓨터에서만 쓰는 채널 이름·핸들은 `template.local.json`(git 제외)이 덮어쓴다.
- 이유
  - 채널이나 스타일을 추가할 때 폴더만 추가한다 (지금 템플릿 6개)
  - 참고 영상에서 잰 값(`templates/yagu_v2/MEASUREMENTS.md`)을 숫자 그대로 옮길 수 있다
  - 채널 그림이 없으면 단색 도형으로 대신해서, 공개 저장소에서도 그림 없이 바로 돌아간다
- 대가: 렌더 방식이 둘(classic·card)이라 필요한 설정 블록이 다르다. `mode` 필드와 검증기로 모드별 필수 블록을 강제하고,
  `Template.card_layout`·`lyrics_box` 속성이 모드에 맞는 설정만 돌려주게 했다.

## KBO 기록은 자동 수집하지 않고 붙여넣기로

- 확인 (2026-10-10): KBO 공식 사이트 robots.txt 가 `User-agent: *` / `Disallow: /` 이고, 사전 승인 없는 자동 수집을
  금지한다는 문구가 있다.
- 결정: ShortsMaker 는 기록 사이트에 접속하지 않는다. 사람이 확인한 표를 정해진 양식(`순위 | 선수 | 팀 | 기록 | 연도 | 장면 설명`)
  으로 붙여넣는다. 자료 정리용 보조 도구(별도 저장소)도 KBO 주소는 코드에서 막고, 사용자가 기록실 표를 복사해
  붙여넣는 기능만 둔다.
- 그래서 양식 읽기를 엄격하게 만들었다: 붙여넣은 자료에는 사람 실수가 섞인다. 줄 번호가 붙은 오류, '확인 필요' 칸 거부,
  열 밀림 검사, 가사와 표 대조가 모두 이 결정에서 나왔다.
- 네트워크를 쓰는 곳은 위키미디어 공용 공식 API(사진 검색)와, 사용자가 비용을 승인했을 때의 OpenAI 이미지 생성뿐이다.

## 연출 바꾸기 엔진 (`variation.py`)

- 배경: 템플릿 하나로 만들면 영상마다 화면 구성과 흐름이 똑같아져서 시청자가 새로 볼 것이 없다.
  영상마다 구성·해설이 달라야 한 편 한 편의 품질이 유지된다.
- 결정
  - 연출 18요소(전환·강조색·자막 등장·인트로·효과음·진행 표시·엔딩 등)를 `Variation` 모델 하나로 묶는다
  - 렌더할 때마다 조합을 `projects/_history.json` 에 남긴다
  - 최근 5편과 3요소 이상 달라야 최종 렌더를 허용한다 (`conflicts`)
  - 추천(`suggest`)은 무작위 후보 4,000개 중 조건을 통과한 것 가운데 최근에 덜 쓴 값이 많은 조합을 고른다
  - 카드 디자인은 무작위가 아니라 영상 분위기에 맞는 것 중 최근에 안 쓴 것 (`suggest_design`)
  - 제목 색·채널 로고는 채널 정체성이라 고정한다
- 한계: 연출만 바꾼다고 좋은 영상이 되지는 않는다. 영상마다 다른 해설·관점이 더 중요해서, 가사 검사(`lyrics_check`)와
  사람이 고친 내용 기록(`production_log`)을 같이 둔다.
